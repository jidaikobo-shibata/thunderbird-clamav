# 内蔵検査方式（0.20.0a13 試用版）

このブランチの実験版は、現行の画面・受信検査・フォルダー検査・履歴・確認メモ・通知・隔離・完全削除を、アドオン内蔵の検査処理へ接続します。合成メール専用の0.1.0試作とは別の成果物です。

## 利用条件と導入

- Ubuntuの通常版Thunderbird 153系を維持し、macOSのHomebrew版ClamAVへ対応しました。Ubuntu 153.7.0esrの既存検証とmacOSの検証は下記のとおりです。Snap/Flatpak、Windows、他のメジャーバージョンは未検証です。
- OSにClamAVとPython3が必要です。検査処理の追加Python/npm依存はありません。ClamAVの導入にはパッケージ管理による依存の追加が必要な場合があります。常駐サービスの登録は不要です。
- 検証済みのPython検査処理をXPIに同梱し、Python3で必要時に起動します。補助プログラムの別途設置・Native Messaging登録・個別更新は不要です。
- Experiment APIを使うため、インストール時にはThunderbirdとコンピューターへの全面アクセス権限が必要です。完全削除・手動隔離などの確認画面は維持しています。
- 旧版を削除せず、実験版のXPIを上書きインストールします。同じアドオンIDを維持し、既存の設定・履歴を引き継ぎます。新規インストール時の自動検査は無効です。
- 以前の補助プログラムと接続登録は使用・変更・削除しません。安定版へ戻す場合に備えて残します。

最初は少数のメールを手動検査し、設定末尾のClamAVの状態と既存の履歴・設定を確認してから利用してください。

## 画面

「検査・検査結果・設定・ヘルプ」の4タブです。ClamAVの状態は設定の末尾にまとめ、接続エラー時は設定タブの丸印と状態欄で案内します。更新・削除の手順はヘルプへ簡潔に記載します。独立したセットアップ/アンインストールタブや、移行用の常設案内は設けません。

## バックアップと削除

既存の設定や履歴がある場合、実験版の初回起動時に、移行前の状態をThunderbirdプロファイル内へ別ファイルで保存します。バックアップに失敗した場合は移行を進めません。バックアップの作成・保持は維持しますが、保存場所は画面に常設表示しません。履歴の差出人・件名・判断メモ等を含みますが、本文・添付は含みません。

アドオンを削除しても、このバックアップと、OSのClamAV・Python3・旧版の補助プログラムは残ります。アドオンの通常の設定・履歴・再開情報は、削除で失われる可能性があります。バックアップの自動消去や自動復元は実装していません。

## 再検査の失敗時（0.20.0a3）

再検査が失敗しても前回の結果を保持し、今回の失敗理由を併記します。同じ本文での脅威検出は維持し、隔離できます。本文が変わっていた場合は前回の結果を参考情報として残し、現在の本文で検出した扱いにはしません。「検査失敗」の絞り込みでも確認できます。再検査で確定した新しい結果が得られれば更新します。

## フォルダー検査前の状態確認（0.20.0a4）

開始・再開の直前にClamAVの状態を確認します。未導入や通信不能の場合は検査を開始せず、設定内の状態欄へ移動します。履歴と停止中の進捗は保持します。導入後は改めて開始・再開でき、過去の確認結果だけで開始を許可しません。

### OSごとの扱い

- Ubuntuの実行パスと定義パス、親消失通知、仮想メモリー制限は維持しています。
- macOSはCPUに応じた標準Homebrew配置とpython.orgの固定候補を探索します。候補とリンク先の親ディレクトリ、所有者、書込み権限、実行可否、バージョンを確認します。Homebrewの管理者グループによる書込みは信頼境界に含めます。同じ利用者や管理者がインストール済みプログラム自体を改変する攻撃への防御は提供しません。
- macOSはLinuxの資源制限を同じ強さと見なさず、OSのプロセス情報を用いて検査グループとMIME解析子の実メモリー量を監視します。CPU時間、経過時間、MIME構造の制限も維持します。メモリーの定期観測は瞬間的な増加を完全には防ぎません。監視不能・上限超過は接続終了または未検査・失敗となり、未検出にはしません。
- macOSのclamd起動待ちは最大180秒、初回接続を含む要求は45秒、検査要求全体は360秒です。Ubuntuは従来の60秒・15秒・225秒を維持します。設定画面の10〜120秒は検査エンジン本体の上限で、定義の読み込み時間とは別です。
- 同じアドオンIDとデータ形式を維持し、設定・履歴・確認メモ・移行前バックアップを引き継ぎます。メールやUIからの任意コマンド、実行パス、シェル、任意ClamAVオプションの指定は追加していません。

## 保存失敗からの復旧（0.20.0a10）

起動時の初期化を「接続を再確認」から再試行できるようにしました。初期化失敗時は案内を表示して変更操作を止め、復旧するまで検査を開始しません。定期表示更新では初期化を再試行せず、移行前バックアップが必要な場合は成功するまで書き込み・検査へ進みません。新しいフォルダー検査の開始保存に失敗した場合は、以前のジョブ・対象・カーソル・チェックポイントへ戻します。

`--scenario recovery`は検証用XPIだけに保存失敗を注入し、初回起動の失敗から実際の確認ボタンで復旧すること、履歴・確認メモ・旧進捗を保持することを使い捨てプロファイルで確認します。配布XPIには故障注入コードやテストAPIを含めません。

## 通常移動時の履歴更新（0.20.0a11）

隔離以外の移動・Undo・アカウント間移動でも、実際の移動イベント・ヘッダー情報・本文ダイジェストを照合して既存の履歴の識別子と場所を更新します。検査待ちに本文が未取得であれば、一意なイベント対象へ検査を向け直し、取得済み本文と移動先が異なる場合は失敗として扱います。検査中に古いヘッダーで移動先を上書きしないよう、必要に応じて移動先を再照合します。再照合は上限を設けています。

コピー・曖昧な候補・未確認の本文は誤って統合せず、確認メモを保持します。既存の重複履歴の自動削除は行いません。合成メールの実移動と往復移動後の再通知・確認メモ保持は、通常の統合試験に含めています。


## 監査後の競合対策（0.20.0a12）

設定の変更要求を順番に処理し、保存成功後に実行中の設定へ反映します。履歴などの保存待ちがあっても、古い設定を書き戻しません。保存できなかった設定は自動検査や待機中メールへ適用しません。対象から外れた検査待ちは、保存済み設定に基づいて起動時にも未検査へ整理します。

新着通知が移動通知より先に届いた場合も、移動イベントと本文SHA256で同一性を確認し、自動生成された移動先の履歴を既存履歴へまとめます。検査中の場合は完了後に照合します。同じ条件の確認メモを保持し、新しい検査結果を反映します。別のメールのコピー、変更された本文、独立した確認メモや隔離処理・異なる自動隔離の設定がある履歴は統合しません。既存の確認判断と新しい結果が食い違う場合も両方を残します。


## パフォーマンス監査の反映（0.20.0a13）

履歴を固定32分割、再開用チェックポイントを256項目ずつのページとして保存します。変更した履歴の分割とチェックポイントのページだけを書き込み、索引とデータを同じstorage.local.setへ含めます。保存要求の順序と要求時のスナップショットを維持し、失敗時は保存済みの基準を進めず次回に差分を再送します。ページが失われた場合は初期化を停止し、空の履歴で上書きしません。履歴の削除・検査ジョブの削除では不要になったページの内容も消去します。

旧形式は読み込み可能です。内蔵方式では既存データの形式移行前にバックアップを保存し、失敗した場合は移行せず接続再確認からの復旧を待ちます。旧版の初回移行バックアップと同時に保存した場合は共有します。既に利用中の旧形式から更新する場合は最新データを別途保存します。旧版への直接のダウングレードは非対応で、戻す場合には移行前バックアップの復元が必要です。

通常移動の本文照合は専用の直列キューへ分離し、新着メールの受付キューを塞がないようにします。候補はヘッダー情報で索引化し、本文のダイジェストは同一の移動イベント内だけで共有します。処理の合間にイベントループへ制御を戻し、追跡していないメールごとのタイマーは避けます。新着優先になっても、曖昧な候補・内容相違・人手の判断の保護は維持し、照合中に完了した新しい再検査結果を古い結果で上書きしません。

隔離先の候補と表示名はフォルダー一覧ごとに計算して再利用します。設定の有効/無効や消失した隔離先の表示はその都度反映し、フォルダー一覧の再取得では候補と表示名を再計算します。

合成データ（履歴1000件・チェックポイント10万件）の簡易計測では、スナップショットと書込対象のJSON生成が中央値約72msから約1.4ms、書込対象が約13.37MiBから約56KiBになりました。実ストレージやIMAP・ClamAVの速度は含まないため、全体の検査時間の短縮率ではありません。
