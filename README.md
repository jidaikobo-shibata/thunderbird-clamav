# ClamAV Mail Check

受信メールをローカルのClamAVで1通ずつ検査するThunderbird拡張です。
定期検査用のclamリポジトリから分離して、独立したGitリポジトリで管理します。
既存の定期検査スクリプト・cron・ClamAVサービス設定は変更しません。

## 初期版の機能

- 指定アカウントの新着メールを順に検査。自動検査は初期状態では無効。
- メール一覧の右クリック、または結果画面から選択メールを手動検査。
- 差出人・件名・検査日時・定義バージョン・検出名・失敗理由を表示。
- 検出・検査不能・失敗をデスクトップ通知。通知に差出人・件名は含めない。
- 結果から対象メールをThunderbirdのタブで開き、標準操作で移動・削除できる。
- 選択したメールを、検査結果の状態にかかわらず対象確認後にごみ箱を経由せず完全削除できる（検査待ち・検査中・削除済みは対象外）。
- 再検査、完了した検査履歴の消去。

通常の検査では削除権限を要求しません。完全削除を使う場合だけ、任意の
`messagesDelete`権限を利用者が許可します。メールの変更・移動・送信権限はありません。
検査結果があるメールの自動隔離や自動削除も行いません。
本文を開く操作ではHTMLが表示され得るため、検出メールは確認を挟みます。

## 対応環境と必要なもの

- Ubuntu / Linux。対象実機バージョンはThunderbird 153.7.0esr（64ビット）。
- マニフェストの最低バージョンはThunderbird 140。ただし140での実機検証は未実施。
- Python 3.10以降、`/usr/bin/python3`。
- `/usr/bin/clamscan` と更新済みのClamAV定義。1.5.4でローカル検査を確認。
- 検査用の補助プログラムはPython標準ライブラリのみ。
- GUIセットアップにはGTK 4.10以降とPyGObject（Ubuntuの`python3-gi`、
  `gir1.2-gtk-4.0`）が必要。確認した環境には導入済み。
- 配布用GUIセットアップのビルドには`/usr/bin/cc`が必要。起動用の小さな
  Linux実行ファイルを生成する。利用者側にCコンパイラーは不要。
- JavaScriptのテストにはNode.js 22以降。

GUIセットアップの対象はUbuntuの通常版Thunderbirdです。
Snap・Flatpak版のNative Messaging連携は未検証のため、選択すると導入・更新を停止します。
サンドボックスの権限を広げる設定を自動で追加することはありません。
利用者のThunderbird 153.7.0esrで導入・接続・手動検査・新着自動検査・脅威検出を確認済みです。
IMAP移動後の再特定と完全削除の実機動作は検証待ちです。

## 構成

`thunderbird/` がMailExtension、`native/host.py` がNative Messaging用の
補助プログラムです。検査処理には追加のPythonパッケージや常駐HTTPサーバーは不要です。
拡張から64KiB以下のデータ片を順に渡し、補助プログラムはSHA-256で
一致を確認してからClamAVを実行します。

初期版では、メールごとに`clamscan`を標準入力で起動します。
検査上限・暗号化の警告を呼び出し時に指定でき、既存の`clamd`設定や
ソケット権限を変更せずに検査不能を判別するためです。
小さなテストメールで1通約4.7秒を要しました。大量受信時には待ち時間が増えます。
設定を確認した`clamd`による高速化は今後の課題です。

メールデータをClamAVに渡す際、シェルを使いません。
補助プログラムには任意のコマンド・ファイルパスを受け付ける機能がありません。
Thunderbird標準の「ウイルス対策ソフトが受信メールを個別に隔離できるようにする」
設定、および`clamonacc`は使いません。

リポジトリのルートで実行します。

```bash
python3 -m unittest discover -s tests -v
node tests/mail_core.test.mjs
node tests/mail_background.test.mjs
node tests/mail_results.test.mjs
node tests/mail_folder.test.mjs
node --check thunderbird/background.js
node --check thunderbird/dashboard.js
python3 scripts/build_mail_check.py
```

`dist/clam-mail-check-0.12.0.xpi` と、確認用の補助プログラム・登録JSONを
`dist/native/` に生成します。GUI不要の導入用ファイル
`dist/clam-mail-check-installer-0.12.0.pyz` をXPIに同梱し、単体でも生成します。
旧GUI配布物も必要な場合だけ `--legacy-gui` を指定します。この場合はCコンパイラーが必要です。
`dist/clam-mail-check-setup-0.12.0-linux-<architecture>.tar.gz` に生成します。
旧GUI配布物にはXPI・補助プログラム・GUIを同梱します。通常配布のXPIにもCLI導入用ファイルが入り、ソースのチェックアウトは不要です。
生成しただけではインストールされません。旧GUIの起動用実行ファイルはビルドした
アーキテクチャ向けです。今回の確認対象はUbuntu 26.04 / x86_64です。

実際のClamAVとの接続確認は次のコマンドで実施できます。
通常メール・EICARの添付・ZIP内EICAR・暗号化メールをメモリ内で生成します。
メールアカウント・ネットワーク・普段のThunderbirdプロファイルは使いません。
ClamAV内部の展開用一時ファイルは、所有者だけが読める一時ディレクトリで扱い、
正常終了・例外・タイムアウト時に後始末します。

```bash
python3 scripts/smoke_mail_check.py
```

画面の操作・文字列の安全な表示・狭い画面でのレイアウトは、別プロファイルの
ヘッドレスChromeで確認できます。実行にはGoogle Chromeが必要です。
ローカル専用HTTPサーバーには画面のアセットと架空のデータだけを渡します。

```bash
node scripts/smoke_mail_ui.mjs
```

GUIセットアップの実際の画面操作は、独立したヘッドレスWestonとD-Bus、
分離した設定・一時的な設置先で確認できます。X11・Xwaylandは使いません。
GTK 4とWeston、dbus-run-sessionが必要です。実ユーザーの登録先は変更しません。
起動のみ・確認キャンセルで書き込みがないこと、導入・修復・削除、
Snap選択時の停止、アプリ一覧用Desktop Entryの起動を検証します。

```bash
python3 -B scripts/smoke_setup_gui.py
```

## 必要なときだけ補助プログラムの更新・修復を表示（0.9.4）

導入済みの補助プログラムより同梱版が新しければ「補助プログラムを更新」、
同じ版で設置ファイルに不整合があれば「補助プログラムを修復」を表示します。
同じ版で正常ならボタンは非表示で「更新・修復は不要です」と表示します。
更新と修復の両方が必要な場合は更新を優先し、確認画面の表現もボタンに合わせます。
導入済みのほうが新しい場合は、同梱版による更新・修復を提示せず、版を下げないようにします。
比較は数値で行い、例えば0.9.10を0.9.4より新しいと判定します。末尾の0は同じ版として扱います。
未導入・接続不能・管理機能未対応の場合は従来の導入コマンドを案内します。
「修復が必要です」はClamAV本体ではなく補助プログラムの設置状態です。

## 保存先を選んで導入用ファイルを保存する（0.9.2）

導入用ファイルの保存は通常リンクではなく、[Thunderbirdのdownloads API](https://webextension-api.thunderbird.net/en/esr-mv2/downloads.html)を使用します。
「導入用ファイルを保存」「再導入・削除用ファイルを保存」を押すと、初回は任意のファイル保存権限を要求し、
保存先を選ぶ画面を開きます。許可しなかった場合・保存を中止した場合・失敗した場合も画面に結果を表示します。
保存開始だけを完了とせず、完了状態を確認して保存パスを表示します。
保存名が変更された場合は、表示・コピーするTerminalコマンドも保存した名前に合わせます。
ファイルはXPI同梱の内容で、保存しただけでは設置や削除を行いません。
追加するdownloads権限は任意で、ボタンを押した時だけ要求します。自分の保存処理のIDだけを照会し、他の保存履歴は検索しません。
補助プログラムの更新は、この保存UI修正のためには不要です。

## セットアップ・アンインストールと右端のヘルプ（0.9.1）

タブは「検査｜検査結果｜設定｜セットアップ｜アンインストール｜ヘルプ」の順です。
ヘルプを常に最後に置き、導入と削除の入口も常に見えるようにします。
狭い画面では3列2行に折り返し、キーボードの左右・Home/Endでも移動できます。
タブのみスクロール位置に固定し、フォーカスが隠れないようスクロール余白を設けます。

- セットアップ：導入状態・版、同梱CLIファイル保存、初回導入、更新・修復、導入確認、ClamAVの接続確認。
- アンインストール：削除するもの・残すものを説明し、1つの「手順へ」の入口から状態に応じた手順へ進む。
  対応済みは画面内で補助を削除し、旧版等では途中だけTerminalの操作を案内する。タブを開くだけでは変更しない。
- ヘルプ：従来の検査範囲に加えて、導入・修復・再導入、削除の手順、削除するもの／残すもの、通常更新との違いを記載。
  セットアップ・アンインストール各タブへの移動ボタンを設ける。
- 設定には自動検査・通知・履歴管理を残す。接続確認と導入・削除の操作は移動する。

初回の導入状態確認後、管理機能未対応または接続不能ならセットアップ、補助削除済みならアンインストールを表示します。
利用者が既にタブ移動した場合や検査対象の確認を開く場合は、画面を勝手に切り替えません。
補助プログラムの処理・権限・保存データ形式は0.9.0と同じです。XPIだけを旧版削除なしで上書き更新できます。

## アドオンから導入・管理する（0.9.0、推奨）

配布するXPIに、Python標準ライブラリだけで実行できる導入用ファイル`installer.pyz`を同梱します。
通常配布に別のGUIアプリ・GTK・CPU別の起動バイナリは不要です。現在はLinuxの通常版Thunderbird向けです。
Python 3と更新済みClamAVはOS側に必要で、Snap/Flatpakとの連携は未検証です。
導入用ファイルはネットワークからコードを取得せず、同梱内容だけを設置します。

1. XPIを旧版削除なしで上書きインストールし、「セットアップ」タブを開きます。
2. 「導入用ファイルを保存」で`clam-mail-check-installer-0.12.0.pyz`を保存します。
3. 保存先のフォルダーをTerminalで開き、アドオンに表示されたコマンドを実行します。
   保存時の名前が変わった場合はコマンドのファイル名も合わせてください。
4. Terminalに表示される変更先と影響を確認して承認します。root/sudoは不要で、実行を拒否します。
5. アドオンに戻って「導入を確認」を押します。設置が有効で管理機能に対応した場合は版と状態が表示されます。

```bash
python3 -I ./clam-mail-check-installer-0.12.0.pyz install
```

導入済みなら同じコマンドで更新・修復します。既存の旧GUI方式の設置記録（format 1）も引き継ぎます。
新方式はformat 2で管理し、GUIアプリとアプリ一覧の起動項目は設置しません。
以前の起動項目は管理記録と一致した場合だけ取り除きます。メール・拡張・拡張の設定と履歴は変更しません。
未知の登録・手動変更した登録・シンボリックリンクは上書きせず停止します。

対応済みの補助プログラムがあれば「同梱版へ更新・修復」「アンインストール」をアドオンから実行できます。
対象パス・影響の確認を要求し、確認チケットは5分・1回限り。同梱ファイルの固定構成・サイズ上限・版を確認し、
古い版への更新や確認後の登録変更は拒否します。管理中は検査・削除の新規実行を止めます。
検査・削除が実行中の場合は管理操作を始められないため、先に停止してください。

### アンインストールから導入テストする

現在の旧補助プログラム（0.6等）には管理機能がないため、最初の削除はTerminal経由です。
「アンインストール」タブの「アンインストールの手順へ」を押します。旧補助などの場合は、その環境に必要なTerminalの手順を途中で表示します。

1. 新着メールの自動検査をオフにし、検査を中止して停止を待ちます。再導入用に同梱の導入用ファイルを先に保存します。
2. 保存先のフォルダーで次のコマンドを実行し、削除内容を確認して承認します。
3. Terminalで削除の完了を確認し、「アンインストール」タブの手順内で確認チェックを入れて「拡張の削除へ進む」を押します。
4. Thunderbirdの自己削除確認で承認します。設定・検査履歴・再開情報は失われる可能性があります。
5. 再びXPIをインストールし、上記の`install`コマンドと「導入を確認」で初回導入を試せます。

```bash
python3 -I ./clam-mail-check-installer-0.12.0.pyz uninstall
```

対応済みならアドオン内の「アンインストール」で補助プログラムを削除し、続いてThunderbirdの確認で拡張自身を削除します。
補助プログラムはこのOSユーザーで共通なので、他のThunderbirdプロファイルからの接続も失われます。
削除対象は管理記録に一致したファイルと接続登録だけ。メール・アカウント・ClamAVは残し、手動変更や未知のファイルは残して表示します。
拡張の削除を取り消した場合は、アドオン内の「拡張の削除を続ける」で再試行できます。
補助プログラムを再導入する場合は保存済みのCLIファイルを使ってください。
接続不能だけでは削除済みと断定せず、Terminalでの完了確認を求めます。
削除の応答が失われた場合は完了未確認として検査を停止し、状態確認・CLIからの修復に進めます。
拡張の削除には[ThunderbirdのuninstallSelf](https://webextension-api.thunderbird.net/en/esr-mv2/management.html#uninstallself-options)を使い、追加のmanagement権限は要求しません。

状態だけの確認（読み取りのみ）と、隔離した設置先での自動テストは次のとおりです。

```bash
python3 -I ./clam-mail-check-installer-0.12.0.pyz status
python3 -B -m unittest discover -s tests -p 'test_cli_setup.py'
```

CLIの自動テストは一時的なホーム相当ディレクトリで導入・更新・削除を3回繰り返します。
実ユーザー環境は変更しません。Thunderbird自身の削除確認は模擬APIで検証し、実環境での操作は利用者が行います。

## 旧GUIセットアップ（互換経路）

**ここからはユーザー環境への導入です。確認画面で承認した時点で変更します。**

1. 配布用のtar.gzをファイル管理画面で展開します。
2. 展開したフォルダーの`ClamAV-Mail-Check-Setup`を起動します。
   テキストのスクリプトではなくLinux用実行ファイルです。実行の確認や
   実行許可の操作が必要な場合は、配布元を確認したうえで行ってください。
   実際のファイル管理画面でのダブルクリック起動は未検証です。
3. ClamAVの状態を確認します。Thunderbirdの導入方法が不明な場合は、
   確認して通常版を選択します。実行パスだけで判定できない場合は推測しません。
4. 「インストール」を押し、作成先と許可範囲を確認して実行します。
5. 「同梱XPIのあるフォルダーを開く」からXPIを確認し、Thunderbirdへ読み込みます。
6. 以後はアプリ一覧の「ClamAV Mail Check セットアップ」で管理できます。

ソースから確認する場合は、先にビルドし、リポジトリのルートで実行します。

```bash
python3 -B setup.py
```

セットアップは起動時には状態の読み取りだけを行います。各操作は確認ダイアログを
表示し、キャンセルを既定の選択にします。root・sudoは不要です。
許可対象は固定ID`clam-mail-check@local.invalid`の拡張だけです。
設置先はユーザーのホーム配下です。

```text
$HOME/.local/lib/clam-mail-check/releases/<release-id>/
$HOME/.local/lib/clam-mail-check/installation.json
$HOME/.mozilla/native-messaging-hosts/local.clam_mail_check.json
$HOME/.local/share/applications/clam-mail-check-setup.desktop
```

- 「更新／修復」では新しい設置先を用意し、ClamAVとの通信が確認できてから
  登録を切り替えます。書き込み中の例外では変更済みの登録を元に戻します。
  電源断など、プロセス自体が中断された場合の完全な自動復旧は未対応です。
- 修復用の元データも変更されていた場合は、ダウンロードした配布物から
  セットアップを起動してください。古い版への更新は拒否します。
- 元のGUIを削除しても、設置済みのコピーをアプリ一覧から起動できます。
- アンインストールは補助プログラムと接続登録・起動項目を対象にします。
  ClamAV本体・Thunderbird拡張・メール・拡張の履歴には触れません。
- 設置記録のハッシュと一致しない手動変更ファイルは削除せず、残った場所を表示します。
  登録JSONや起動項目が別物の場合は、上書き・削除せず停止します。
- 排他制御用の小さなロックファイルと空の管理ディレクトリは残る場合があります。
- 以前のCLI方式で登録した環境は、設置記録が異なるため自動移行しません。
  既存の登録を確認し、移行方針を決めてから対応してください。
- 補助プログラムにGUI・OS設定を変更する通信命令は追加していません。
  更新と削除は、利用者が独立したセットアップ画面から実行します。
- 自動ダウンロード・自動更新・他OS対応は未実装です。

## Thunderbirdへの読み込み

1. 実機検証ではまず別のテスト用プロファイルを使います。
2. 「アドオンとテーマ」からアドオンのデバッグ画面を開きます。
3. 「一時的なアドオンを読み込む」で、ビルドしたXPIまたは
   `thunderbird/manifest.json`を指定します。
4. メール検査のボタンから結果画面を開き、ClamAVとの接続を確認します。
5. 架空のテストメールを選択し、右クリックから手動検査します。
6. 問題がなければ「新着メールを自動検査するアカウント」にチェックを入れます。そのアカウントの自動検査を開始し、自動保存します。

一時的な読み込みはThunderbirdの再起動で解除されます。
通常のXPIインストールは、そのビルドの署名ポリシーに従います。
署名確認やセキュリティ設定を変更する手順は含めません。

## 選択したメールの完全削除（0.7.0）

「選択したメールを完全削除」は、未検出・検出・未検査・失敗を混ぜて選択した場合も使えます。

個別の「完全削除」も同じ対象です。特定できないメール、確認後に内容や場所が変わったメールは削除せず理由を表示します。
任意の削除権限、全対象の確認、元に戻せない旨の確認、期限付きの一回限りチケットは維持します。
検査待ち・検査中・削除済みのメールは選択対象外です。

補助プログラムや速度改善処理の変更はありません。0.6.1からはXPIのみ更新できます。
更新は旧版を削除せず「ファイルからアドオンをインストール」で上書きしてください。

フォルダー検査と新着・手動検査の受付で同じルールを使います。
フォルダー検査の集計と再開用データは履歴の入れ替えによって失われません。
0.6.0導入済みならXPIのみの更新で利用できます。

## 中止したフォルダー検査の再開・削除（0.6.0）

- 中止・中断・上限による停止・失敗の検査には「再開」を表示します。再起動・拡張更新後も
  自動再開せず、利用者の操作で再開します。同じ実行IDを維持するので、以前の結果とまとめて絞り込めます。
- 再開時は元のフォルダーと選択済みのサブフォルダー範囲を再列挙します。
  識別情報のハッシュと本文全体のSHA-256の両方が一致した処理済みメールだけ、ClamAVでの再検査を省きます。
  Thunderbirdの一時ID・並び順には依存しません。同じ内容のコピーも処理済み件数分だけ省きます。
  同じ識別情報で本文が変わった場合や、本文照合に失敗した場合は検査対象に残します。
- 検査済みメールの照合には本文の取得が必要なので、IMAPでは通信が発生する場合があります。
  新着・移動・削除などで対象が変化した場合、総件数を「以前の処理済み件数＋今回の未処理件数」に更新します。
  本文を取得できず失敗したメールなど、照合情報がないものは再検査し、今回の処理として追加集計します。
- 再開用データはメールの識別情報のハッシュ・本文ハッシュ・同一内容の件数のみです。
  本文・添付・一時ID・未処理の対象一覧は永続化しません。履歴1000件の上限と独立して保持します。
  再開用のキーは対象上限100000種類までで、それを超えて記録できない分は再検査します。
- 0.4/0.5から更新した場合、残っている結果履歴のハッシュから処理済み情報を復元します。
  既に履歴が失われている分は再検査します。旧版では再開情報がなかったための制限です。
- 「検査記録を削除」は確認画面を表示し、進捗と再開用データを消します。
  メール本体と各メールの検査結果は残ります。実行中は削除できないため、先に中止してください。
  結果履歴を消すだけでは再開用データは消しません。
- 保持するフォルダー検査は最新1件です。新規検査を開始すると前回の再開情報を置き換えます。
- 補助プログラムの検査処理は0.5.0と同じです。0.5.0導入済みならXPIのみの更新で構いません。
  0.4以前から高速化も利用する場合は、最新セットアップで補助プログラムも更新してください。

## 連続検査の高速化（0.5.0）

- 拡張と補助プログラムの両方を更新してください。新しい配布物を展開して
  セットアップを起動し、「更新／修復」で補助プログラムを更新した後、同梱XPIを読み込みます。
  検査中の更新は避け、先に中止して停止を待ってください。中断したフォルダーは0.6.0以降の「再開」で照合して続行できます。
- Linuxの`/usr/sbin/clamd`が利用可能な場合、連続検査中だけ専用の前景プロセスを起動します。
  最初の定義読み込みは1回のみです。2通目以降は同じNative Messaging接続・同じ定義を使います。
  待ち行列を処理し終えた場合や中止後、接続を閉じて専用プロセスと一時領域を解放します。
- 既存のClamAVサービスやOS設定は変更しません。定義は`/var/lib/clamav`から読みます。
  既存daemonとは別の定義をメモリに保持するため、検査中の追加メモリが必要です。
  専用daemonの起動は最大60秒、検査は最大120秒で打ち切ります。
- 初期起動に失敗した場合や`clamd`がない場合は、その接続では従来の`clamscan`を利用し、
  結果の詳細に明示します。稼働中のdaemonとの通信失敗は「検査失敗」にし、
  daemonを終了させます。その後のメールは通常方式に戻して検査します。
- 25MiB／展開後100MiB／10000ファイル／深さ16／検査エンジン内60秒の上限、
  暗号化・上限超過の通知、フィッシングURL判定無効を専用設定で維持します。
  使用中の定義日時を毎回確認し、3日を超えて古い場合は検査失敗とします。
  定義の再確認は60秒間隔、再読込時は処理を待たせてメモリの二重使用を抑えます。
- 所有者のみがアクセスできる一時ディレクトリとUnixソケットで
  [INSTREAM](https://docs.clamav.net/manual/Usage/ClamdProtocol.html)を使い、
  メールのバイト列を送信します。TCP接続・任意のファイルパス指定は受け付けません。
  daemonの暗号化・上限の通知や診断の警告は「未検査」として扱います。
  INSTREAMは最初の検出で終了するため、従来のallmatch検査より検出名が少ない場合があります。
  未検出を含め、安全を保証するものではありません。
- 通常の終了・タイムアウト時に一時領域を削除します。Linuxの親プロセス終了通知で、
  補助プログラムが異常終了した場合も専用daemonを終了させます。
  強制終了・電源断時の一時ディレクトリの残留には未対応です。
- 接続確認は利用可能性とバージョンの確認です。daemonの起動と実検査は検査開始時に行います。
  実際にdaemonで検査した結果のエンジン表示には`(clamd)`が付きます。

連続Native Messaging接続での実ClamAV検証（模擬メールのみ）は次のとおりです。
`--require-clamd`は通常方式へのフォールバックを成功と扱わない指定です。

```bash
python3 -B scripts/smoke_mail_check.py --require-clamd
```

## フォルダー検査と進捗（0.4.0）

既存環境ではXPIだけを更新します。補助プログラム・GUIセットアップの再登録は不要です。
追加の権限・依存ライブラリはありません。

1. Thunderbirdの受信・同期を完了させ、フォルダー一覧で通常のメールフォルダーを
   1つ右クリックし、「ClamAVでフォルダーを検査」を選びます。
   「検査」タブのアカウント・フォルダー選択からも開始できます。
2. アカウント・フォルダーパスを確認し、必要な場合だけ「サブフォルダーも含める」を選びます。
   初期状態は選択したフォルダーだけです。
3. 「検査を開始」を押します。検査タブで対象確認中の状態を表示し、
   一覧取得後は確定した対象件数に対する進捗バーと割合を表示します。
4. 結果が1通ずつ追加されます。「この検査の結果を表示」で、同じ実行の結果に
   絞り込みます。状態・アカウント・文字列の絞り込みや一括処理も併用できます。

進捗には処理済み/対象件数、検査中/未処理件数、未検出・検出・未検査・失敗の内訳、
経過時間を表示します。処理済みには検査不能と失敗も含み、安全の保証にはしません。
読み上げ用の進捗通知は状態変化と10件ごとの節目にまとめ、経過時間を毎回読み上げません。

- フォルダー検査は同時に1件。対象のヘッダー情報を一覧取得し、実際の履歴への
  登録とClamAV検査は1通ずつ行います。新着と手動検査を優先します。
- 対象はThunderbirdが列挙したメールです。対象確定後の新着はこの実行には追加せず、
  通常の新着検査に任せます。IMAP本文の取得には通信・待ち時間が発生し得ます。
- 統合受信トレイ・検索・タグなどの仮想フォルダーとアカウント直下のルートは対象外。
  子フォルダーの取得にはAPIの階層情報を使い、仮想の子フォルダーは除外数を表示します。
- 対象一覧の取得に失敗した場合は停止します。空のフォルダーは0件で完了します。
  メモリ上の対象は最大10万通、走査するフォルダーは最大5000件に制限し、超過時は
  検査を開始せず停止理由を表示します。範囲を分けて検査してください。
- 「中止」は、実行中の一覧取得または1通の検査が終了してから停止します。
  未処理件数は残し、完了とは表示しません。「再開」で処理済みメールを照合して続行できます。
- 画面を閉じても検査は続きます。Thunderbird終了・拡張更新などで中断した場合は、
  再起動後に中断状態を表示し、自動再開しません。処理中だったメールは結果未確認として残します。
- 実行中の対象一覧やThunderbirdの一時的な数値IDは保存せず、進捗の集計だけを
  履歴と別に保存します。メール本文・添付は進捗データにも保存しません。
- 履歴上限は1000件のままです。古い未検出・完全削除済み結果が置き換わっても進捗の集計は保持します。
  検出・未検査・失敗などで履歴が埋まり、新しい結果を残せない場合は、その時点で停止します。
- 集計は検査時の結果です。履歴消去、完全削除、手動再検査後の状態とは区別します。
  手動再検査で更新した結果は、元のフォルダー検査だけの絞り込みから外れます。
- フォルダー検査のエラーは集計を安定させるため自動再試行しません。必要なら結果一覧から再検査します。
- 通知設定が有効なら、最初の検出・最初の未検査/失敗を通知し、終了時に合計を通知します。
  フォルダーパス・件名・差出人はデスクトップ通知に含めません。
- フォルダー検査はメールを削除・移動しません。削除には従来どおり利用者の確認が必要です。

## 検出時の通知と完全削除

「検出・検査不能・失敗をデスクトップ通知する」を有効にすると、該当時に
通知します。通知には差出人・件名を含めず、クリックすると結果画面を開きます。
実際の通知表示・保持はOS側の通知設定にも依存します。

完全削除は0.2.0で追加しました。既存環境では拡張のXPIだけを更新できます。
補助プログラムの再登録やGUIセットアップの更新は、この機能のためには不要です。
固定IDが同じ拡張を更新し、既存の設定と検査履歴を継続利用します。

1. 削除したい結果行で「完全削除」を押すか、チェックボックスで選択し「選択したメールを完全削除」を押します。
2. 初回はThunderbirdの削除権限確認で許可します。既に許可済みなら対象確認に進みます。
3. 差出人・件名・アカウント・フォルダー・状態・検出名を確認します。
4. 元に戻せないこと、IMAPではサーバーと他端末にも反映されることを確認し、実行します。

- 0.7.0以降は未検出・検出・未検査・失敗が対象です。検査待ち・検査中・削除済みは対象外です。
- 本文を表示せず、検査時のSHA-256があれば現在のメール全体と照合します。
  ハッシュがない場合は、確認時にメール全体の照合用ハッシュを作り、実行時に再計算して比較します。
  この照合は512KiB以下の分割データと直前のハッシュをSHA-256で連鎖させ、サイズも含めます。
  検査上限25MiBを超えたメールでも全体を一括でメモリに載せず照合できます。
  照合用ハッシュは確認チケット内のメモリだけに保持し、検査済みの意味は持ちません。
- 確認後も再照合し、内容・場所の変更、対象消失、複数候補、権限不足の場合は停止します。
- 確認は60秒で期限切れになり、1回限り有効です。キャンセル時は削除しません。
- 成功時は履歴を「完全削除済み」にし、検出名と削除日時を残します。
- 自動削除、確認の省略は行いません。失敗時の自動再削除もしません。
- Thunderbirdの完全削除APIを使用し、ごみ箱を経由しません。実メールの削除は
  自動テストでは行わず、模擬APIと独立したヘッドレス画面で検証しています。

## 状態と制限

| 状態 | 意味 |
|---|---|
| 検査待ち / 検査中 | まだ結果は出ていません |
| 未検出 | 指定範囲で脅威を検出しませんでした。安全の保証ではありません |
| 脅威候補を検出 | 検出名を表示します。誤検知の可能性もあるため人が判断します |
| 一部または全部が未検査 | 暗号化、サイズ・展開上限、ClamAVの警告など |
| 検査失敗 | 未導入、通信失敗、取得失敗、定義が古い、タイムアウトなど |

- 検査は受信後です。本文表示や添付ファイルを開く操作を止めません。
- 1通25MiB、展開後合計100MiB、展開ファイル数10000、再帰16段が上限。
- エンジン検査は60秒、定義読み込み等を含むプロセス全体は120秒が上限。
- 定義が3日超古い場合、`clamscan`の機能で検査を失敗として扱います。
- URLの評判によるフィッシング判定は、既存のメール検査運用に合わせて無効。
  HTMLや添付に対する通常のマルウェア検査は実行します。
- OpenPGP・S/MIMEメールは復号しません。暗号化部分は検査不能として表示。
- IMAPの本文取得に追加の通信が生じる場合があります。ヘッダーのみのメールは
  本文をダウンロードしてから再検査してください。
- 検査失敗は60秒後に1回再試行します。自動検査を止めると自動分の再開も止まります。
  実行中の1通は完了まで進めます。手動検査は自動検査の設定に依存しません。
- 新着の対象はThunderbirdの受信イベントです。過去メール全体や拡張停止中の
  受信を網羅する追跡機能はありません。必要なメールは手動検査してください。

## 履歴と対象メールの特定

履歴はThunderbirdの拡張専用ローカル保存領域に最大1000件保持します。
差出人・件名・アカウント/フォルダー識別情報・日時・メール全体のSHA-256・
検査結果を保存します。本文と添付は履歴に保存しません。
OSのユーザー権限で読める情報であり、履歴自体の暗号化は行いません。

上限では古い未検出・完全削除済み結果から置き換えます。それ以外で満杯の場合は新規受付を
停止し、結果画面とバッジで通知します。確認後に履歴を消去してください。
表示は1ページ50件で、ページ送りにより履歴全体を確認できます。期間での自動削除はありません。

Thunderbird内部の数値IDは再起動後に再利用しません。
再起動・移動後はMessage-ID、アカウント、差出人、件名、日時、必要に応じて
SHA-256を照合します。複数候補・Message-IDなし・消失したメールは推測で開かず、
メール一覧から選択して再検査するよう案内します。
添付の削除やヘッダー変更などで内容が変わった場合も再検査が必要です。

- キーボード操作、読み上げ、拡大表示。色だけでは状態を区別しません。
- 通常のメール操作への負荷。`clamscan`方式は大量受信で待ち時間が増えます。

## 補助プログラムの更新案内（0.9.5）
Thunderbird起動時と「導入を確認」で状態を調べます。同梱版への更新が必要なときは、セットアップタブの右上とツールバーアイコンの右上に小さな丸を表示します。修復・接続確認が必要な場合も丸で案内します。詳細はツールチップと読み上げ用のラベルで確認でき、タブ名や大きな案内枠は増やしません。

ツールバーは確認が必要なメール件数を優先し、その場合は検査結果を開きます。補助プログラムの案内だけならセットアップを直接開きます。正常になれば丸は消えます。接続失敗だけでは未導入・修復と断定せず、削除済みの場合は再導入を催促しません。更新は同梱の補助プログラムとの比較で、インターネット上の最新版確認ではありません。


## 日本語・英語の表示（0.10.0）
Thunderbirdの表示言語に合わせ、日本語（ja）または英語（en-US向けの表現）を使用します。他の言語では英語へフォールバックします。独自の言語切り替え設定は設けていません。画面、通知、右クリックメニュー、確認ダイアログ、ツールチップ、読み上げ用ラベル、ヘルプ、導入・削除手順を対象にしています。日付も表示言語に合わせます。

翻訳は`thunderbird/_locales/ja/messages.json`と`thunderbird/_locales/en/messages.json`に格納し、Thunderbird標準のi18n APIを使用します。`mailNNN`は既存の説明に対応する安定したキーです。番号の付け直し・再利用はせず、新規メッセージは新しいキーを追加してください。文中の値は名前付きプレースホルダーで渡し、翻訳や値をHTMLとして挿入しません。元の日本語は翻訳者向けのdescriptionと、拡張APIのない単体テスト用フォールバックにも保持しています。

補助プログラムには要求ごとに言語を渡します。新しいネイティブ検査説明は翻訳キーと生の検出情報を分けて保持し、表示時に翻訳できます。従来の履歴の説明文、差出人、件名、検出名、ClamAVやOS自身の診断出力は書き換えません。古い補助プログラムの日本語の説明は、補助プログラムを更新するまでそのままです。

Terminalに提示するコマンドには`--language ja`または`--language en-US`を付け、Thunderbirdと同じ言語で導入・削除手順を表示します。指定がなければLC_ALL、LC_MESSAGES、LANGの順に参照し、日本語以外では英語にします。既存の導入用ファイルの構成を保つため、Python側の翻訳表は`setup/__init__.py`と`native/host.py`に内蔵しています。Python側を変更したら、拡張の翻訳表・検査説明の翻訳キーとの一致も確認してください。旧GUIセットアップは互換用であり、今回のローカライズ対象には含みません。

検証は`node --test tests/mail_*.test.mjs`、`python3 -m unittest discover -s tests`、`node scripts/smoke_mail_ui.mjs`で行います。画面検証は独立したヘッドレス環境と模擬APIで日英を確認し、実Thunderbirdの言語パック設定には触れません。


## フォルダーの表示名（0.10.1）
検査対象の一覧・確認・進捗・結果の場所・削除確認では、Thunderbird APIのnameと親子関係から作る「親 › 子」の表示を使用します。IMAP内部パスを表示名として使わず、識別には従来どおりaccountId・id・pathを使用します。アカウントのルート名はフォルダー階層に含めません。旧履歴の場所は同じアカウント・パスの現在のフォルダー情報を参照します。フォルダー一覧を取得できない場合は保存済みの名前、名前もない旧データのみ内部パスを予備の表示に使います。履歴そのものを一括書き換えたり、フォルダーを改名したりはしません。


## フォルダーの絞り込みと複数選択（0.11.0）
検査タブのフォルダー選択をチェックボックス一覧に変更しました。アカウントを選び、表示名・親の名前で候補を絞り込んで複数選択できます。「表示中を選択」は絞り込み中の候補を追加選択し、「すべての選択を解除」は隠れた選択も解除します。絞り込みで隠れた選択は保持し、件数を明示します。アカウントを変えると選択と絞り込みを解除します。ダッシュボードを閉じた場合の選択自体は保存しません。

開始前の確認には隠れた選択を含め全対象を一覧表示し、サブフォルダーを含めるか選択できます。サブフォルダーを含める親と子を同時選択しても、APIで同じフォルダーと分かる対象を重複列挙・検査しません。別フォルダーに保存された同じ内容のコピーはそれぞれ検査します。対象は同一アカウント内です。

複数の選択を1件のフォルダー検査として実行し、全対象の合計進捗・結果を表示します。進捗の「対象フォルダー」で選択した一覧を確認できます。中止・再開・記録削除も検査全体に適用します。再開時はすべての元フォルダーの場所を確認し、1つでも欠けたり移動した場合は開始せず案内します。旧版の単一フォルダーの再開情報にも対応します。既存の受信検査優先・履歴上限・中止時の処理完了待ちを維持します。


## 監査結果の修正（0.11.1）
- clamdの診断ログは前回までに読んだ位置を保持し、新しく増えた部分だけを判定します。過去の警告や累積ログサイズだけで、後続の正常メールまで未検査にしません。今回のログが上限を超えた場合は今回の結果を未検査として扱います。
- 設定タブの「停止中の自動検査の待機を取り消す」で、自動検査オフまたは対象アカウントから外れた待機を確認付きで取り消せます。未検査の待機記録を除いて容量を空けます。失敗からの再試行待ちは失敗記録に戻し、元の説明を残して自動再試行を止めます。実行中の検査、手動検査待ち、既存の検出・未検査・失敗履歴、メール本体は取り除きません。失敗履歴で上限に達している場合は、従来の履歴整理も必要です。停止したフォルダー検査は、その後「再開」で続けられます。
- 補助プログラム側も版番号を4要素に0埋めして比較します。0.11.1と0.11.1.0のような同じ版の修復を拒否しません。古い版による更新拒否は維持します。
- 検査結果の検索は、内部パスに加えて表示中のフォルダー名と親の名前を対象にします。

XPIを削除せず上書きし、補助プログラムも更新してください。ログ判定と版比較の修正は、補助プログラムを更新してから有効になります。


## 自動検査をアカウントの選択に統一（0.12.0）
独立した有効化チェックを外しました。「新着メールを自動検査するアカウント」にチェックするとそのアカウントの自動検査を開始し、最後のチェックを外すと停止します。変更は自動保存し、動作中のアカウント名または停止中であることを表示します。保存に失敗した場合はチェックと状態表示を元に戻します。通知設定は独立して変更できます。

移行時は旧設定のenabledがfalseなら対象アカウントを空にし、trueなら対象を引き継ぎます。旧版で停止中だった環境は、アカウント選択が保存されていても勝手に検査を開始しません。内部のenabledは互換用に維持し、新しい画面では選択の有無から設定します。対象を覚えたまま一時停止する独立操作は設けません。待機の取消しは引き続き設定タブで行えます。
